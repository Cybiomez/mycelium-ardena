# Журнал решений

## 30-09-2026 — фаза 1

- **python-telegram-bot, а не aiogram.** Замер: процесс с одним импортом aiogram — 164 МБ ОЗУ (модели всех типов Bot API через pydantic), python-telegram-bot + aiohttp — 55 МБ. Бокс — 2 ГБ.
- **Бот не привязан к токену.** Токен, владелец, группа — из окружения; имя бота — из `getMe`. Обкатка на токене Altsy, смена бота — без правки кода.
- **Токен при первой установке взят из конфига старого Altsy** (`CLAUDE_TG_TOKEN_FROM`), а не из Vaultwarden: хранилище было заперто, мастер-пароль вводит только Алексей. Файл `~/.config/claude-tg/env` (600) — тот же формат, что даёт `secret render`. **Исправить:** переустановить с `BW_SESSION`, когда Алексей будет у терминала.
- **Режим прав — только «Авто» в фазе 1.** В демоне `canUseTool` разрешает всё, кроме `AskUserQuestion`, поэтому «с подтверждением» и «План» сейчас не дали бы реального подтверждения. Переключатель режимов появится вместе с кнопками разрешений и утверждения плана (фаза 3, доработка демона №3).
- **Реакции 👀 (в очереди) и 👌 (в буфере)** вместо ⏳ и 📎 из ТЗ: Telegram разрешает реакции только из своего списка, ⏳ и 📎 в нём нет.
- **Удаление темы не отслеживается:** Telegram не присылает боту такого события. Привязка удалённой темы остаётся в базе, пока не придёт ошибка отправки. Не мешает работе.
- **Защита от инъекций неполная.** Чужой текст (пересланное, цитаты, буфер) оборачивается пометкой «данные, не инструкции», но модель может ей не последовать. Сессия работает в режиме «Авто» — риск принят (ТЗ §11), смягчение: только владелец может отправить ход, 2FA Telegram, `/panic`.
- **Состояние вопросов и отложенных подтверждений — в памяти процесса.** Перезапуск бота во время открытого вопроса теряет кнопки; вопрос можно снять `/stop`.
- **Темы = все рабочие сессии** (решение Алексея 30-09-2026, вместо служебных тем «Напоминания»/«Журнал» и ручного `/attach`). Каждая непустая сессия демона получает тему; новые появляются сами (сверка раз в минуту), переименование сессии переименовывает тему. Пустые сессии (0 сообщений) пропускаются.
- **Зеркало ходов из VS Code/терминала** в тему — вопрос и итоговый ответ, беззвучно. Отличаем по полю `entrypoint` записей транскрипта: `sdk-ts` — ходы через демон (бот, Pocket), их не зеркалим. Ход считается завершённым по `stop_reason: end_turn`; незавершённый перечитывается со своего начала. Историю до привязки не выкладываем — зеркало начинается с конца транскрипта. Ходы Pocket в тему пока не попадают (осознанно: Pocket, вероятно, закроем).
- **Напоминания (фаза 2):** по делу сессии — в тему этой сессии; личные, не связанные с сессией — в TGChat.
- **Дублирование ходов — только по запросу** (решение Алексея 30-09-2026, вечер). Ни ходы из VS Code/терминала в тему сессии, ни копии из чужих чатов/инлайна в TGChat автоматически не дублируются. Флаг на тему: `/mirror on|off` (по умолчанию off). При включении показываются только новые ходы (offset = текущий конец транскрипта), старое не выкладывается. Причина: авто-дубль зашумлял темы; последнее сообщение проще спросить в самой теме.

## 02-10-2026 — фаза 2 (проактивность)

- **Сессию, вызвавшую MCP-инструмент, определяем по соединению** (`caller.py`): порт клиента → сокет в `/proc/net/tcp` → процесс → `--resume <id>`; потомок демона → выполняющийся ход демона; иначе самый свежий транскрипт (≤ 2 мин). Подстановка `${CLAUDE_CODE_SESSION_ID}` в заголовок **не работает**: сам процесс Claude этой переменной не имеет (только его дочерние), заголовок приходил пустым, а у процесса, запущенного из другой сессии, — с чужим id. Только Linux. Слабое место — новая сессия VS Code без `--resume` при параллельной работе нескольких сессий: эвристика «свежий транскрипт» может ошибиться. Тогда напоминание уйдёт не в ту тему — не потеряется.
- **MCP-сервер свой** (JSON-RPC поверх aiohttp, ~200 строк) вместо SDK `mcp` (62 МБ). Слушает `127.0.0.1:8790`, вход по токену. Токен лежит в `~/.local/share/claude-tg/mcp-token` (600) и в `~/.claude.json` (регистрация `claude mcp add --scope user`) — оба вне git, сервер только на localhost.
- **Модель/effort на отдельное задание не задаются.** В демоне настройки привязаны к сессии: разовое задание навсегда сменило бы модель темы. Задание идёт с настройками своей темы.
- **Повторяющееся напоминание не «пинает»:** следующий срок считается сразу при отправке, без ожидания «Сделано». Разовое — повтор через 3 ч без ответа, до 3 раз. «Отложить» у повторяющегося создаёт разовую копию, расписание не трогает.
- **Задание в сессию, открытую в VS Code, откладывается на 10 мин** (иначе два процесса в одном транскрипте); об этом — одна беззвучная строка в теме.
- `/panic` глушит и планировщик.
