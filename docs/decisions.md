# Журнал решений

## 30-09-2026 — фаза 1

- **python-telegram-bot, а не aiogram.** Замер: процесс с одним импортом aiogram — 164 МБ ОЗУ (модели всех типов Bot API через pydantic), python-telegram-bot + aiohttp — 55 МБ. Бокс — 2 ГБ.
- **Бот не привязан к токену.** Токен, владелец, группа — из окружения; имя бота — из `getMe`. Обкатка на токене Altsy, смена бота — без правки кода.
- **Токен при первой установке взят из конфига старого Altsy** (`CLAUDE_TG_TOKEN_FROM`), а не из Vaultwarden: хранилище было заперто, мастер-пароль вводит только Алексей. Файл `~/.config/claude-tg/env` (600) — тот же формат, что даёт `secret render`. **Исправить:** переустановить с `BW_SESSION`, когда Алексей будет у терминала.
- **Режим прав — только «Авто» в фазе 1.** В демоне `canUseTool` разрешает всё, кроме `AskUserQuestion`, поэтому «с подтверждением» и «План» сейчас не дали бы реального подтверждения. Переключатель режимов появится вместе с кнопками разрешений и утверждения плана (фаза 3, доработка демона №3).
- **Реакции 👀 (в очереди) и 👌 (в буфере)** вместо ⏳ и 📎 из ТЗ: Telegram разрешает реакции только из своего списка, ⏳ и 📎 в нём нет.
- **Удаление темы не отслеживается:** Telegram не присылает боту такого события. Привязка удалённой темы остаётся в базе, пока не придёт ошибка отправки. Не мешает работе.
- **Защита от инъекций неполная.** Чужой текст (пересланное, цитаты, буфер) оборачивается пометкой «данные, не инструкции», но модель может ей не последовать. Сессия работает в режиме «Авто» — риск принят (ТЗ §11), смягчение: только владелец может отправить ход, 2FA Telegram, `/panic`.
- **Состояние вопросов и отложенных подтверждений — в памяти процесса.** Перезапуск бота во время открытого вопроса теряет кнопки; вопрос можно снять `/stop`.
